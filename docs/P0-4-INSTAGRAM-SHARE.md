# P0-4 — Instagram → CoupleReels 공유 수신

## 범위

- Android 공유 목록에서 `CoupleReels` 앱 이름과 분홍색 링 아이콘으로 표시되도록 `mvp` 수신 액티비티를 등록한다.
- `ACTION_SEND` / `text/plain` 또는 `image/*`의 `EXTRA_TEXT` 안에서 **개별 Instagram Reel URL**만 추출한다. 추적용 쿼리 문자열을 제거한 정규 URL을 사용한다. 이미지 전송에서 URL이 빠진 경우 자동 분석을 하지 않고 링크 붙여넣기를 안내한다.
- 앱이 이미 열려 있어도 새로 실행해도 공유 링크를 수신하며, 로그인 전 수신했다면 로그인 후 확인창을 표시한다.
- 전용 핑크색 바텀시트에서 태그를 직접 고르고 `내 취향에 반영하기`를 눌러 저장한다. 지난번 선택 태그는 다음 공유 시 재사용할 수 있지만 사용자가 바꿀 수 있다.
- 공유 URL은 사용자 개인 `saved`에 비공개로 저장한다. 취향 태그는 릴스를 공유할 때 누적하고 동일 URL은 보관함에 중복 저장하지 않는다.
- 커플을 연결하지 않아도 개인 취향을 저장할 수 있다. 연결 후 상대는 공유 원본 URL이 아닌 취향 태그 및 제외 해시를 통해 다른 후보 릴스를 추천받는다.
- 별도 재생 검증용 `app` 모듈은 시스템 공유 대상에서 제외한다. `mvp`가 유일한 사용자용 공유 대상으로 표시된다.

## 실제 기기 수동 QA — 아직 수행 전

1. 새 버전 `com.couplereels.mvp` 설치 후 **Instagram 앱의 실제 릴스**에서 공유 버튼을 눌러 앱 목록에 CoupleReels가 나타나는지 확인한다. 위치는 Android가 결정하므로 하단 첫 줄 고정은 보장하지 않는다.
2. CoupleReels를 선택하고 공유한 Reel URL이 앱 내부의 확인창에 표시되는지 확인한다. 이미지 공유 시 함께 전달된 텍스트에 URL이 있으면 받으며, 일반 이미지로 공유된 경우 링크가 없을 수 있으므로 저장되지 않고 안내가 떠야 한다. Android가 공유 대상의 표시 순서를 결정하므로 스크린샷과 같은 하단 첫 줄 노출은 보장하지 않는다.
3. 처음 가입한 뒤 커플 연결 없이 릴스를 공유하고 태그 하나를 선택해 저장한다. 보관함의 URL과 취향 태그가 사용자 계정에 저장되어야 한다.
4. 같은 Reel URL을 추적 파라미터만 바꿔 재공유하고 중복 안내·하나의 저장 항목·누적 태그를 확인한다.
5. 로그아웃 상태에서 링크 공유 → 로그인 → 링크가 사라지지 않고 확인창이 나타나는지 검증한다.
6. 초대 코드로 두 계정을 연결한다. 다른 계정이 원본 URL이나 개인 `saved`를 읽지 못하고, 상대용 추천 후보에서도 원본이 제외되는지 검증한다.
7. 연결을 해제해도 개인 취향과 저장 내역이 남고, 상대방 접근은 차단되는지 확인한다.
8. 회전·백그라운드 복귀·취소·오프라인·서버 타임아웃 시 공유창 상태와 저장 중복 방지를 검증한다.

## 운영 전 차단 조건

- 이 브랜치의 `firebase/firestore.rules`에 사용자 전용 `preferences/taste` 권한이 추가됐다. 운영 Firebase에 **검토·배포 전**에는 원격 비연결 취향 저장이 PERMISSION_DENIED가 될 수 있다.
- 현재 서버와 무관한 로컬 Fake 모드는 한 기기 내 테스트 용도이며 다른 휴대폰과 동기화되지 않는다.
- Instagram 버전·OS마다 실제 공유 페이로드가 다를 수 있어 Galaxy S25+에서의 실측이 필요하다.
- 실제 Instagram Reel 앱 내 재생 및 유사 Reel 탐색 API의 정상 작동은 이 변경으로 검증되지 않았다.
- 첫 APK 전체에 적용할 A-1 릴스 전체화면/4탭 UI는 이 공유 수신 패치와 별도의 전면 UI 작업이다. 본 작업은 공유 진입·확인창과 색상 기초를 우선 구현한다.

## 보안 원칙

- 앱이 공유받은 원본은 사용자 고유 저장 경로에 보존하고, 커플 공유 취향 문서에는 원본 URL을 기록하지 않는다.
- 동영상 내용은 자동으로 분석하지 않으며 태그는 사용자가 직접 선택한다.
- 상대방의 취향 태그를 앱 화면에 직접 나열하지 않는다. 현행 추천 엔진은 상대 태그를 클라이언트가 읽는 구조이므로, **암호학적 의미에서 상대방에게 태그 내용이 비공개라는 보장은 아직 없다.** 이 요구가 필요하면 서버 측 추천으로 이전해야 한다.
