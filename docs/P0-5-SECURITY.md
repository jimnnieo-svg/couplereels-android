# P0-5 개인정보·Firebase 검토

운영 규칙 배포, 운영 데이터 변경, 권한 변경은 수행하지 않았습니다.
`google-services.json`은 현재 checkout에 없고 주입된 Firebase 자격 증명도 없습니다.
이번 APK는 **기기 내부 로컬 체험**이며 두 휴대폰 서버 동기화가 검증된 정식 서비스가 아닙니다.

## 확인한 데이터 경계

- `users/{uid}` 및 `saved`, `preferences/taste`: 본인만 읽고 씁니다.
- `couples/{cid}`: 128비트 초대 코드로 대기 커플에 합류합니다. 다른 커플 목록 조회 금지.
- `tastes`, `events`: 활성 커플 구성원에게 읽기가 허용됩니다. 본인 취향/이벤트만 작성합니다.
- 연결 해제 후 규칙은 공유 읽기를 거부합니다. 클라이언트는 partnerTaste와 listener generation을 초기화합니다.
- 계정 변경 때 Firebase listener를 제거하고 AppData를 비웁니다. UI 후보 분류는 모드+uid로 분리됩니다.
- 로컬 체험 저장소는 계정별 목록을 분리하지만 앱 내부에 여러 체험 계정이 들어 있습니다. 실제 인증 서비스 또는 암호화된 비밀 저장소로 간주하지 마세요. 실제 비밀번호 사용 금지.
- Android 12+ 클라우드 백업과 기기 이전에서 앱 데이터 경로를 제외했습니다. 기존 기기 데이터를 삭제하지 않습니다.

## 완전 비공개가 아닌 이유 (중요)

상대 클라이언트는 취향 태그와 제외 원본의 SHA-256 해시를 읽습니다. 태그는 읽을 수 있으며,
후보 URL이 한정된 경우 URL마다 해시를 계산해 원본을 추측할 수 있습니다. 이벤트 태그/시각도 공개됩니다.
따라서 “내 취향 답변은 상대에게 그대로 보이지 않는다”, “원본의 존재를 절대 알 수 없다”는 보장은 하지 않습니다.
UI는 원본 링크를 **직접** 전달하지 않으며 추천용 태그를 서로 공유한다고 안내합니다.
연결 해제 전에 상대가 이미 읽은 정보를 원격 삭제하거나 회수할 수는 없습니다.

완전한 비공개가 필요하면 서버 측 추천과 서버 전용 제외 정보, 최소 집계 결과만 전달하는 별도 설계가 필요합니다.
이번 작업에서 서버를 새로 배포하거나 기존 개인정보 계약을 조용히 변경하지 않았습니다.

## 규칙 변경과 운영 적용 조건

시안의 패션·향수·꽃·맛집·여행·전자기기·취미·골드·화려함을 기존 11개 태그에 추가해
클라이언트/로컬 규칙 모두 20개 태그를 허용하도록 맞췄습니다. 알 수 없는 태그는 계속 거부합니다.
기존 운영 규칙이 남아 있다면 새 태그 저장은 권한 오류로 실패합니다. 성공 메시지는 표시하지 않습니다.
규칙 파일 변경으로 기존 verification-status.json의 기록은 새 소스 검증을 의미하지 않습니다.
기존 BLOCKED 보고서는 수정하지 않았으며 배포 guard는 계속 배포를 막습니다.
운영 적용 전 공식 Emulator의 10개 테스트, 실제 두 계정·두 기기 테스트, 규칙 검토와 별도 배포 승인이 필요합니다.

## 재생·추천 한계

Instagram 전체 콘텐츠 검색/수집, 스크래핑, 영상 다운로드, 인증 제한 우회는 없습니다.
기존 10개 실제 URL만 후보이며 현재 공개 여부/재생은 보장하지 않습니다. 수동 태그와 가중 Jaccard 점수로 순위를 매깁니다.
미분류 후보는 내용이 비슷하다고 단정하지 않습니다. 자동 분석이나 무제한 후보 수집을 주장하지 않습니다.
공식 임베드는 사용자가 요청할 때만 로드하며 페이지 로드 완료를 재생 성공으로 기록하지 않습니다.
재생 제한 안내, Instagram에서 열기, 링크 복사를 제공합니다. 기존 P0-1 수동 재생 기록 기능은 개발 진단에 보존했습니다.
